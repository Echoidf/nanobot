# 自然任务抽屉 UI 设计说明

## 项目目标

NanoDesk 是高频使用的 AI Agent 工作台，核心体验是连续对话和工具执行。此次能力不是在 ReAct 之外增加一个需要用户切换的独立模式，而是让 LLM 在任务复杂时自然创建结构化任务列表，宿主按任务执行并把状态及时同步到 WebUI；简单问题仍直接回答。用户始终停留在同一条对话流中。

## 用户场景

长任务通常包含 3 到 12 个任务，可能持续数分钟或更久。执行期间用户可能补充条件、改变目标、声明某项工作已经手动完成，或说明某项任务不再需要。用户消息必须优先于启动下一任务，LLM 处理消息后通过结构化任务工具更新列表，而不是要求用户操作一套项目管理控件。

## 信息模型

任务抽屉呈现目标摘要、revision、总体进度、当前任务、任务总数、每项状态、依赖、失败或阻塞原因、最近更新时间和关键证据。任务状态为 `pending / running / completed / cancelled / blocked / failed`。状态同时使用图标和文字，颜色不是唯一编码。

界面不展示“进入任务模式”“关闭模式”“取消计划”“暂停计划”或步骤操作菜单。取消是单项任务状态，不是一种全局模式动作。任务列表的创建、完成、取消、替换和结束均由 LLM 在理解用户对话后调用工具完成；有歧义时通过对话澄清。

## 选定方向：输入框任务抽屉

升级现有 `GoalStateStrip`：默认显示当前任务、完成数量和总体进度；展开后在输入框上方展示完整只读任务列表。输入框执行期间始终可用，并明确提示用户可以随时补充进度或改变要求。

用户发送打断消息后，抽屉短暂显示“正在处理你的更新”，Host 不再启动新任务。LLM 调用任务工具成功后，列表原位更新，并显示一次轻量反馈。例如用户说“测试我已经手动执行过了，全部通过”，对应测试任务更新为 completed，证据标记为“由用户手动完成”。

任务列表全部完成或不再相关后，输入框任务条自动淡出；会话历史保留一条简短归档摘要。

## 视觉基线

沿用 NanoDesk 的中性浅色背景、青色主色 `#1686a8`、暖灰边框、紧凑的 12-14px 工具排版。避免卡片套卡片、装饰性渐变和项目管理后台式按钮。桌面以 1440x900 为目标，窄屏以 390x844 为目标；长任务列表在抽屉内部滚动，不横向溢出。

## 验收点

- LLM 可在复杂任务中自然创建任务列表，简单对话不出现抽屉。
- 输入框在执行期间可用，用户消息优先于下一任务调度。
- WebUI 原位显示 pending、running、completed、cancelled、blocked 和 failed。
- 用户声明手动完成工作后，LLM 调用工具更新正确任务和证据。
- 多个任务匹配时先澄清，不猜测。
- 抽屉没有全局模式开关、取消计划按钮、暂停按钮或步骤菜单。
- 原型仅用于评审，不连接真实后端。
